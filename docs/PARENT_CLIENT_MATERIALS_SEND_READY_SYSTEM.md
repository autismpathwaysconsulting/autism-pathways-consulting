# APC Parent Client Materials — Send-Ready System

Status: INTERNAL OPERATING SYSTEM

Purpose: reduce the time between a paid session and sending parents something useful. The system intentionally limits the number of parent-facing documents.

## 1. Core rule

Do not create a new bespoke report from scratch after every session.

Use a small set of reusable templates and fill only the sections relevant to the current concern.

## 2. RM350 One-Concern Parent Session

### Parent-facing deliverable
**One document only: APC One-Concern Action Note**

Recommended length: 1–2 pages.

Required fields:
1. Main concern discussed
2. What we noticed / parent-reported pattern
3. Working hypothesis
4. Priority for now
5. 1–2 practical changes to test
6. What to observe
7. When to review / when another professional may be needed

### Optional attachment
Only if directly relevant:
- One-Minute Pattern Check
- Who Does What note
- one APC resource link

Do not attach the full implementation toolkit.

### Production workflow
Before session:
- open the Action Note template,
- pre-fill parent name/date/concern from intake.

During session:
- capture only short phrases under Pattern / Hypothesis / Priority / Actions.

Final 5 minutes:
- verbally confirm the priority and 1–2 agreed actions with the parent.

After session:
- spend a short documentation block turning the notes into parent-ready wording,
- send within the agreed service window.

## 3. RM1,800 Home Implementation Programme

### Parent-facing documents
Use only two standard formal documents across the whole programme.

### A. APC Home Support Plan
One evolving document.

Start after Session 1.

Sections:
- family priority/priorities,
- starting pattern,
- working understanding,
- current agreed plan,
- what adults will do,
- where/when,
- what to observe,
- review date,
- current status: Keep / Adjust / Simplify / Change Direction / Refer.

Do not issue a new polished PDF after Sessions 2 and 3 unless necessary. Update this master document only when the agreed plan materially changes.

### B. APC Maintenance Summary
Send after Session 4.

Recommended length: 1–2 pages.

Sections:
- what the family learned,
- what to keep,
- what to stop,
- what still needs observation,
- early warning signs,
- when to return to APC,
- when another professional route may be more appropriate.

### Between-session communication
Use a short WhatsApp/email message instead of a formal document:

**What we're testing until next time**
- Change: [ ]
- Use it when: [ ]
- Adult response: [ ]
- Watch for: [ ]
- Review at: [next session/date]

This message is the parent’s quick-reference card.

## 4. Session capture fields

For every paid session, capture the same seven fields:

1. **Concern / priority**
2. **Verified or parent-reported pattern**
3. **Working hypothesis**
4. **Agreed adult action**
5. **Context: where/when**
6. **What to observe**
7. **Decision / next review**

If these seven fields are completed, the parent document should be quick to produce.

## 5. File naming

Recommended client-facing filenames:

One-Concern:
`APC_Action_Note_[ParentFirstName]_[YYYY-MM-DD].pdf`

Home programme:
`APC_Home_Support_Plan_[ParentFirstName].pdf`

Final:
`APC_Maintenance_Summary_[ParentFirstName]_[YYYY-MM-DD].pdf`

Do not put diagnosis or sensitive concern details in the filename.

## 6. Minimum design standard

All parent-facing files should use the same simple structure:
- APC logo/name,
- document title,
- family/session date,
- short sections,
- no dense paragraphs,
- no unnecessary clinical terminology,
- scope line in footer.

Prefer a clean 1–2 page document over a long report.

## 7. Send message templates

### One-Concern
Hi [Parent], here is the Action Note from our session. I kept it focused on the one priority we agreed, what to try, and what to observe next. If one part of the agreed plan is unclear, you can send one clarification question within 7 days.

### Home Support Plan
Hi [Parent], here is the current Home Support Plan from Session 1. This is the working version we will review and adjust across the programme. You do not need to do everything at once. Focus only on the current agreed priority and the “What we're testing” message.

### Maintenance Summary
Hi [Parent], here is the Maintenance Summary from our programme. It records what seems worth continuing, what can stop, what still needs watching, and when it would make sense to review the plan again or involve another professional.

## 8. No-change rule

Do not hide lack of change in the document.

If little or nothing changed despite reasonable implementation, write that clearly and record the next decision:
- simplify,
- revise hypothesis,
- change direction,
- coordinate,
- refer.

This protects trust and prevents reports from becoming promotional documents.

## 9. Recording/transcript rule

A recording or transcript is not the parent deliverable.

If APC later uses meeting recording/transcription, it should only support CJ's note capture. The final parent-facing document must still be reviewed by CJ, reduced to the relevant facts/working hypotheses/actions, and checked for privacy and accuracy.

Do not send full transcripts to parents by default.

## 10. Operational target

The intended workflow is:

**intake → session → seven capture fields → template → quick review → send**

The goal is to make documentation repeatable enough that CJ is not designing a new resource after every consultation.
